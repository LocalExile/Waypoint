# Waypoint 0.3.1 — mod startup hotfix

Fixes startup with LocalExile revisions that include the new mod host.
Waypoint now builds the source mods in `Mods/Source/` before starting Gateway, including when using Play,
Start servers, an individual Gateway start or a Gateway restart. Builds are incremental.

- Shows a **Building mods** stage with the current mod name and compiler output in the operation log.
- Stops the requested launch if a mod fails to build, so an older DLL is not silently used as a fallback.
  Correct the reported error and retry. If dependencies need rebuilding, stop servers and use **Build checkout**.
- Preserves LocalExile's existing mod enable/disable choices and binary-only mods.
- Supports older LocalExile branches without `Mods/Source/`.
- Mod preparation works with Gateway code hot reload enabled or disabled.

## Update

Close Waypoint and extract the complete `Waypoint-0.3.1-win-x64.zip` into a new folder.
Open `Waypoint/Waypoint.exe`. Keep all supporting files together.
Settings and backups use the same local storage as 0.3.0; no LocalExile reinstall or save reset is required.
Closing Waypoint leaves services running. Stop services before updating if you want the next launch to exercise
the new mod build step.

## Scope

This is a startup compatibility fix. Mod listing, graphical enable/disable controls and explicit live mod reload
are not included. Use LocalExile's `/mod`, `/mod_enable`, `/mod_disable` and `/mod_reload` commands in game.
Existing ignored mod output folders are not automatically removed when switching branches.
The Windows x64, standard LocalExile layout and other first-alpha compatibility limits still apply.
