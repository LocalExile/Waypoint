# Waypoint 0.4.0 — mod management

Adds a Mods page for LocalExile revisions with the mod host, while retaining older-branch startup compatibility.

## Changes

- Search source and binary mods by ID, version, kind, status or error. Inspect dependencies and source availability.
- Build one source mod or all source mods. LocalExile's file watcher applies rebuilt DLLs independently of Gateway
  code hot reload. The UI does not infer a loaded mod from a successful build alone.
- Enable/disable mods using LocalExile's persistent choices. With Gateway stopped, choices apply on its next start.
  Live controls and confirmed `/mod` status use LocalExile's optional native client helper (Python + Frida, player
  in a playable area). Without it, use the displayed in-game command or stop Gateway before changing choices.
- Reload a selected live mod and inspect the resulting load status. Dependency failures remain explicit.
  Reloads reset mod state and can reload dependents; disabling a dependency can unload other mods.
- Automatic save backups before mod changes, enabled by default with a direct off switch. Backup history records
  mod manifests/versions, binary fingerprints, saved choices and confirmed runtime status when available.
- Restore recorded enable choices separately from saves, while Gateway is stopped. No DLLs are installed/restored.
- Retain removed source mods' unchanged launcher-recorded outputs in local recovery storage rather than letting
  them keep loading after branch changes. Changed outputs require review; third-party mods and extra files remain.
- Branch round trips preserve untracked mod runtime files on older revisions without their ignore rule. Tracked
  changes and other untracked source still block switching.

## Update and use

Close Waypoint and extract the complete `Waypoint-0.4.0-win-x64.zip` into a new folder, then run
`Waypoint/Waypoint.exe`. Settings and backups are retained. Select your checkout and open **Mods**.
Keep all supporting files together. There is no installer or automatic update service.

## Limits

Windows x64, standard LocalExile client/build paths and localhost ports remain the supported runtime layout.
Source builds require the default `Mods/Binaries` output folder. Existing binary-only mods can use a supported
literal profile's `Game_MODS_FOLDER`. Runtime status is labelled last checked and expires after two minutes or an
observed process/file change. This is not an immutable runtime attestation or an upstream control API.
Mod reload does not promise to retain old code after a load failure. Mods execute with LocalExile's user privileges.
No mod downloads/marketplace, DLL installer, script-on-save compiler, custom league selector or catalog editor is included.
External edits and Gateway watcher restarts do not automatically back up every file change.
