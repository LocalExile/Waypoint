# Waypoint 0.6.2 — one workspace window

**Local review build; not published.** Includes the 0.6.0 account manager and 0.6.1 waypoint emblem.

- Opening the same build again brings back the existing window rather than creating another workspace, including
  copies in another folder or with another executable filename. Minimized windows restore, maximized state is
  preserved, and open dialogs remain intact.
- A different build or requested checkout shows a themed notice with the running version/location. Repeated
  launches never switch checkout, overwrite preferences, interrupt an operation or stop a process automatically.
- The guard recovers after exit/crash without stale lock files. Unreachable owners fail closed. The existing
  runtime writer lock and ownership/account safeguards remain active underneath the desktop guard.
- Supported older copies already running are identified. Older binaries launched afterward cannot be forced to
  participate. A visibly marked `--allow-multiple` developer option remains available for deliberate testing.
- Notices follow English/Russian, the selected colors/fonts/text size and Windows High Contrast resources.

Extract the complete **Waypoint-0.6.2-win-x64.zip** into a new folder and double-click **Waypoint/Waypoint.exe**.
Close an older Waypoint normally before using the new build. Settings and backups retain their stable location.
The package includes the .NET Desktop runtime; LocalExile prerequisites are unchanged. This remains an unsigned
Windows x64 early-alpha build. No automatic update, shortcut replacement or process termination is performed.

See [startup behavior and validation](../../single-instance.md) for the developer override, Windows foreground and
legacy limits, native checks and automated evidence. The UI gate applies to the same Windows user/logon session.
